## 3. Verification required during implementation

| Artifact               | Evidence to capture                                                           | Recheck                                            |
| ---------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------- |
| Provider approval      | Date, permitted users/use, jurisdictions, data display, retention, cost units | Before provider-specific work and public use       |
| Capability matrix      | Exact institution/account product, endpoints, scopes, history, limits         | Before each connector release                      |
| Dependency matrix      | Supported stable versions, lockfiles, licences and model digests              | Bootstrap and each dependency update               |
| Auth/security review   | Real role tests, callback/revocation flows, scans and findings                | Every relevant change                              |
| Model evaluation       | Hardware/runtime settings, fixtures, error rates and latency/memory           | Model, prompt or runtime changes                   |
| Financial calculations | Golden cases, independent checks, versioned assumptions                       | Engine/rule changes                                |
| Recovery evidence      | Restore duration, age of restored data, deletion-ledger replay                | Before real use, paid launch, and scheduled drills |
| Commercial model       | Actual quotes, provider usage and settlement statements                       | Before pricing/public rollout, then monthly        |
| Store/legal review     | Applicable storefront/programme, current policy and legal advice              | Immediately before submission/launch               |

Store evidence in private project documentation with secrets and unnecessary personal data removed. Keep source URLs and check dates beside conclusions; do not commit credentials, personal statements or complete production datasets.
